# 0027 — 可恢复材料管理与先预览的知识同步

- 状态：已接受（用户选择 review_then_sync，授权实施；验收见 progress）
- 日期：2026-11-18

## 背景

用户需要清理已读或误导入材料，不能把整理列表等同于撤销已经形成的知识。知识目录重复的“已登记”也容易被理解成概念已经掌握。任务历史需批量收起，但不能丢失正在执行的工作或待选论文。

## 决策

1. 阅读状态、机器处理、材料可见性继续分离。隐藏/取消隐藏只整理材料默认列表，不改阅读、清单成员、原件或知识。回收/恢复是可恢复生命周期：保留items身份、来源、反馈、个人笔记和原件，不物理删除；回收项从阅读清单和后续自动处理排除，恢复时回到默认材料列表并恢复原清单意图。重复导入回收项要求先恢复，不静默另建或补写。
2. schema v14追加material_lifecycle，缺少状态行的旧材料默认可见。只有回收/恢复的真实切换增加revision，隐藏不产生知识撤销任务；确认同步只接受仍匹配的revision，不能吞掉同步期间的新操作。
3. 材料回收不立即写知识页。用户先查看只读变更预览，再确认同步。预览token覆盖材料输入、笔记、来源/生命周期及知识文件；发生变化必须重新预览。同步包含来源状态与已读材料新增/补全文/笔记变化的增量整理，后者共用既有批量预算、输入复用和失败记录，不自动把未读材料登记为已读。
4. 回收同步仅管理wiki_ingest生成页面的material_sync元数据，不删除文件、正文、个人笔记、掌握度或human_relations。对应自动材料页withdrawn；共享概念有其他有效来源时review、无有效来源时unsupported。正式目录/图谱/复习/模型上下文排除withdrawn及unsupported，review仍可见并提示复核；高级视图可看保留内容，恢复后可同步恢复正式可见性。来源标记不是对共享页面所有陈述的重新核验，不自动重写旧段落或抹掉人工内容。
5. 默认知识目录不再重复显示recorded的“已登记”，仅显示legacy、来源待复核等例外。recorded内部含义不变：来源材料登记过阅读，不代表用户掌握全部概念。阅读状态同时用文字与颜色表达：已读绿色、阅读中蓝色、未读黄色/琥珀色，支持现有亮暗主题。
6. 一次清理全部已结束任务历史，复用单条dismiss保护并持久隐藏；运行中与等待选择保留，不取消任务。材料、原件、账单用量与知识不受影响，“包括已关闭”仍可查看。

## 边界

不增加硬删除、自动定时清理或全库强制重写，不自动处理用户现有材料；所有变更由显式管理/同步动作触发。索引重建只更新派生目录，不等于知识内容同步。本文不引入语义向量检索：当前相关页召回仍主要依赖名称/别名，模型看到索引和候选后能够判断语义关系，但不保证漏召回或未知同义归并已解决。PDF补全文沿用原材料入口，扫描版OCR和图表/公式完整读取仍非现有能力。

部署前对持久个人工作区集中备份，验证仅新增生命周期表及派生index变化，不自动隐藏/回收、清理任务或调用模型。M14原生Obsidian缺口保持，不push/PR、不改原.env或launchd。
