# 0018 — 反馈与信源解耦、信源目录、手动添加文章（M11）

- 状态：已接受
- 日期：2026-11-06
- 修订：
  - ADR 0008 / 0013：反馈不再用于调整信源 trust；
  - ADR 0016：低产出停用建议保留；
  - ADR 0007 / M7：sources.yaml 写回不再丢失注释。

## 背景

用户已确认以下决定：

- 反馈只应影响 AI 判断，包括画像、few-shot 和画像修改提案，不应再影响信源配置。
- 信源全部手动维护。用户打算把个人配置清空，再从零逐个添加，偏好 blog。论文投入太大，每天 105 分钟的预算放不下。
- 低产出停用建议保留，因为它只看产出，不看反馈。
- 用户已有大量阅读积累，需要手动补录文章，并区分"已读"和"准备读"，主要用来维护 wiki。

## 决策

### 1. 反馈与 trust 解耦（删除范围）

- 删除以下内容：
  - "按正向比例建议 trust ±1"的逻辑：`profile/tune.py` 中的 `SourceStats`、`source_stats`、`_suggest`、`apply_trust_changes`；
  - `ops.apply_trust`；
  - Web 上的 `/ops`"应用 trust 建议"按钮和 `POST /ops/tune` 路由；
  - `sb sources tune --apply`；
  - settings 中的 `personalize.tune_window_days / tune_min_samples / tune_raise_ratio / tune_lower_ratio`。旧的 settings.yaml 如果还写着这些键，会被忽略，不会报错。
- **CLI 的取舍**：保留 `sb sources tune` 这个命令名，以兼容已有习惯和文档，但它改为**只读**，打印每个信源的 trust、反馈分布与近期产出，以及低产出停用建议。`--apply` 已删除，传入会报错。
- `/sources` 每个信源显示**反馈分布**：各条目当前状态的计数，分为 有收获 / 太浅 / 太难 / 没价值 / 不感兴趣 / 稍后读。这只是参考信息，不附带任何建议。
- trust 仍由用户手动设置，继续参与排序分。

### 2. sources.yaml 按文本块编辑（保留注释）

- 新增 `sources_file.py`。一个条目的范围是：从 `- id: X` 这一行开始，到下一行缩进不大于它的非空行（下一个条目、同级注释或顶层键）之前；末尾的空行不算在块内。
  - **追加**：在文本末尾追加 YAML 块。如果文件是 `sources: []`，先改成 `sources:`。
  - **删除**：删除该块及其后的空行。删光后写回 `sources: []`。
  - **停用 / 启用**：只改块内 `enabled:` 的值，保留行尾注释；块内没有 `enabled:` 时在块末尾添加一行。
- 每次修改都先重新解析、校验（`SourceConfig` 校验、id 唯一），通过后才原子写入；校验失败时文件保持原样。
- `config/sources.yaml` 不存在时，第一次修改会先把 example 的**原文**（含注释）复制过来。M9 起首次编辑会丢注释，这次一并修好。
- Web 表单新建的信源用 `yaml.safe_dump` 生成一个块（两格缩进），追加到末尾。
- `sources: []` 与空的 `sources:` 都是合法的空清单。
- 删除信源只改配置，DB 中的历史条目、反馈与 wiki 都保留。

### 3. 信源目录（从零开始添加）

- `/sources` 新增"信源目录"区：列出 `sources.example.yaml` 中、但不在当前生效配置里的条目（按 id 比较）。每条显示：
  - 名称与主页链接（复用 `source_homepage`）、类型、tags；
  - "论文类"标记（arxiv / hf_papers）；
  - needs_scraper / 停用标记。
- **预览**（`POST /sources/{id}/peek`）：拉取并解析该信源最新约 10 条的标题与日期。不写 DB、不调用 LLM；失败时给出简短原因。已在配置里的信源也可以预览。
- **添加**（`POST /sources/catalog/{id}/add`）：把 example 中这一条的原文（含注释）追加到 `config/sources.yaml`。
- 没有启用的信源时：
  - `sb fetch`、`sb run`、首页"开始今日过滤"都只给出"还没有启用的信源，去 /sources 添加"的提示，不报错、不抓取、不调用 LLM；
  - 首页、/sources、/ops 都能正常渲染。

### 4. 手动添加文章

- **入口**：
  - 页面 `/add`：导航栏"添加"，稍后读页也有链接；
  - CLI：`sb add <url>... [--read|--later] [--feedback gained|too_easy|too_hard|worthless] [--ingest] [--text-file F]`，默认是 `--later`。
- **流程**：Web 中作为后台任务运行，逐个处理，单个失败不影响其他。每个 URL 的结果为"新增 / 已存在 / 失败（原因）"。
  1. **抓取**：
     - arXiv 链接（abs / pdf / html，带不带版本号都行）：用 API 取元数据，正文按现有逻辑取 arxiv_html，取不到再用 PDF；
     - 其他链接：网页正文提取，再用页面元数据补全标题 / 作者 / 日期，与 sitemap 条目相同；
     - 拿不到正文时，如果用户粘贴了正文（仅限单个 URL），就用它，提取方式记为 `manual_text`。
  2. **去重**：按规范化 URL 判断（arXiv 统一为 `https://arxiv.org/abs/<id>`）；正文哈希相同也视为已存在。已存在的条目不重复插入，只更新状态与反馈，原有的信源与状态不变。
  3. **归属**：新条目归到**虚拟信源 `manual`**。它在 DB 中有一行 sources（type = manual，enabled = 0），这样能满足外键、详情页也能显示；但它不在 sources.yaml 里，不参与抓取、产出率和低产出建议，也不出现在 /sources。
  4. **不进流水线**：新条目的 `items.status = manual`，这是新增的状态值，不需要 schema 迁移。流水线只查询 new / l1 / l2 等状态，所以这些条目**不进 L1 / L2 / 分级 / 预算**。
- **状态与反馈**（复用 ADR 0013 的反馈机制，不新建状态表）：
  - 准备读：写一条 `later` 反馈，会出现在"稍后再看"中。
  - 已读并选了反馈：写入该读后反馈，同时设置 `read_at`。
  - **已读、无评价**：只设置 `items.read_at`（保留最早时间），**不写任何反馈行**，当前反馈状态为空。这样不新增 kind，也不破坏 ADR 0013"当前状态 = 最新一次点击"的语义。以后用户在条目上点任何按钮，都按原规则覆盖。
- **编入 wiki**：只有"已读 + 有收获"可以勾选，因为 wiki 队列（`pending_items`）只收当前状态为有收获的条目。勾选后在同一个后台任务里，接着用现有的 `ingest_items` 编入。不勾选时，有收获的手动条目留在首页"待编进 wiki"的计数里。这个计数现在在没有 digest 时也会显示。
- 手动条目的详情页上，深度速读、补前置等按钮照常可用。它们的反馈照常用于画像与 few-shot。

## 后果

- 正面：
  - 信源配置完全由用户掌控，编辑不再丢注释，可以从空配置逐个添加；
  - 阅读积累可以补录进来，用于维护 wiki 与画像。
- 负面：
  - 旧配置中的 `tune_*` 键会被静默忽略；
  - 文本块编辑依赖"每个条目以 `- id:` 开头"的写法（example 与程序生成的块都满足）。手写成 flow 风格（`- {id: x, ...}`）的条目无法按块定位，删除或停用时会提示找不到；
  - 手动条目不进每日推荐，需要从 /later 或详情页访问。
- DB：无迁移。仍是 v8；新增的只是 `items.status = 'manual'` 这个取值，以及 `manual` 这一行 sources。
- 依赖：无新增。
