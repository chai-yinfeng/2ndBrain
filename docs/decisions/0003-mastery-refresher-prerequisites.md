# 0003 — 掌握度、"温故"栏与前置知识

- 状态：已接受
- 日期：2026-11-04

## 背景

原设计把 profile 中"已熟悉的领域"当作降低 novelty 的信号：熟悉的内容只推新进展。但"熟悉 ≠ 掌握"：很多基础知识用户熟悉却不扎实、会遗忘，恰恰需要回炉。把它们一律降权，会让系统把最该复习的讲解类好文过滤掉。同时，读一篇前沿文章时如果依赖的概念不扎实，读的效率很低，系统应该能提示"先回炉什么"。

## 决策

- **掌握度分级**：profile 中每个领域标掌握度 `陌生 / 接触过 / 想回炉（熟悉但不扎实）/ 扎实`，以 Markdown 表格书写，代码可解析（M4 结构化）。
- **L1 额外输出**：
  - `content_type`：`frontier | explainer | survey | tutorial | opinion`；
  - `refresher_value`（0–10）：对用户掌握度为"接触过 / 想回炉"的领域，讲得好的 explainer / survey 加分而不是降权；
  - 对"扎实"领域，只推真正的新进展（frontier），入门讲解降权。
- **独立"温故"栏（refresher lane）**：分级新增 refresher 栏，默认 1–2 条 / 天，**不占** must_read 名额。
- **前置知识**：L2 输出 `prerequisites[]`（该条依赖的概念）；若依赖用户不扎实的概念，UI 显示"建议先回炉：[[概念]]"。
- **复习调度（M6）**：wiki 概念页记录 `mastery`、`last_reviewed`、复习间隔（SM-2 简化版）；UI 按钮"还记得 / 模糊 / 忘了"调整间隔与掌握度；到期概念进入温故栏，若近期采集到讲该概念的好文则一起推。

## 后果

- 正面：系统从"只推新东西"变为"新进展 + 有节奏的回炉"，更贴合学习型使用者；前置知识提示把推荐与 wiki 连起来。
- 负面：L1 / L2 输出 schema 变大，prompt 更长；掌握度需要用户维护（M4 由反馈辅助建议）；复习调度引入额外状态（概念页 frontmatter），lint 需要覆盖。
- 涉及 milestone：M2（L1 / L2 字段、refresher 栏）、M3（反馈按钮"需要回炉 / 已扎实"、前置知识提示）、M4（profile 掌握度表解析与调整建议）、M6（概念页复习字段、`sb wiki due`）。
