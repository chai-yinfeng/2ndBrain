# 0031 — 已读快捷捕获与多端边界

- 状态：已接受
- 关联：ADR 0022、0028、0030

## 已读快捷捕获

在普通导入之外提供明确的「我读完了」入口。输入可以是一个链接、一段带唯一链接的分享文字、明确选择的论文名、上传 PDF 或粘贴正文。暂不猜测无链接的自由描述，不将用户叙述当作原文，不要求撰写笔记。入口的提交文字必须说明是否调用 AI，并展示模型输入范围。普通入口依旧只保存，不因前端参数而获得快捷整理授权。

材料身份优先走现有公开标识、URL、已核验书目和正文/文件指纹；不能因为标题相似自动合并。论文歧义需用户确认候选；等待候选、重新启动和取选不能变成盲目重放模型调用。只从真正持久保存的材料继续登记和整理。对于链接来源的网络/公开正文提取失败，保留原链接及明确的已读事实和可见的失败原因；不把引用、摘要或用户话语当全文。只凭链接或摘要不自动生成知识，提示补正文。用户提供正文或 PDF 时通过现有导入入口沿用该来源，无需重访失败站点。整理失败不撤销已读或原文；提供独立重新授权入口，不自动续跑付费任务。

## 时间回顾（后续，不在本轮实现）

- “上周看过什么”以用户登记的阅读事实为准，不用文章发布日期、导入时间、机器整理时间替代。第一版可以用现有 `read_at`（首次阅读登记时间），独立展示整理/导入状态，允许列表按日期分组并选点高亮 Web 图谱；不按时间重排知识边。
- PDF、文章和视频的直接材料节点按选中日期范围高亮；进一步区分「这些材料直接支持的概念」与「普通相邻节点」。没有生成知识页的材料仍出现在时间列表，不为了高亮制造节点或关系。
- 日后若需要重读、补录真实阅读日期或跨设备共享历史，增设持久的阅读事件（唯一事件 ID、发生时间、登记时间及来源），不覆盖首次登记时间、不伪造历史重读。按用户时区划周，不随设备切换改变已发生事件。

## 手机、Mac 和同步（现在保留边界，不实现客户端）

1. 第一步先以现有响应式 Web 验证主流程和真实回顾需求，再增加系统分享接收；iOS、macOS 或其他界面的入口都走同一导入/已读服务，不各自实现去重和付费逻辑。
2. 第一期跨设备建议一个权威工作区和持续可达的服务：设备只是访问它，不同步运行中的 SQLite 文件。设备接入前需要明确身份认证、授权、加密连接、密钥存放与备份，不能把当前默认本机 Web 直接开放到公网。短期以受保护的网络 Web 为主，网络断开不承诺自动同步。
3. 以后若确有多端离线编辑，定义版本化 API、幂等请求与稳定跨工作区 ID；当前 SQLite 整数 ID 和 Web 路径继续有效，不提前迁移数据。同步传递阅读事件、资源引用和有版本的笔记变更；文件内容用校验和去重，编辑冲突不静默覆盖。任务和费用由权威服务管理，避免双端重复整理。原件、个人文字和来源是可迁移数据；检索索引和图谱布局均可重建，不同步其内部文件。
