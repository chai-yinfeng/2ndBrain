# 0030 — 本地阅读记录、按批整理与可验证恢复

- 状态：已接受
- 关联：ADR 0022、0026、0027、0029

## 背景

阅读主要在外部发生。读完有一些概念印象是常态，只有少数材料值得写长笔记；本地记录不应阻塞于笔记表单、可用模型或费用。用户以 Web 图谱为主要浏览入口，不要求原生 Obsidian 给 Web 发版背书。长期保有的资料是 Markdown、原件、两库和配置，不是一个数据库文件。

## 决策

1. 导入、标记已读、保存学习笔记和整理知识是独立操作；日常标已读不弹笔记表单、不初始化模型。短笔记和讨论引用可选，保留本人记录；外部会话链接不抓取。复用现有已读待整理状态，不重新解读历史阅读事实。
2. 已读可选一份或多份，经显式确认调用模型。默认不发送独立学习记录；允许在适用的整理入口显式纳入个人笔记，并说明后端和实际上下文。批次复用缓存与单次费用控制，分项报告失败；一次提交不等于合成一次 LLM 调用，也不据此承诺降低单篇 token。主题级合并、关系更新收益和代价需后续用样本验证。
3. 整理依旧尊重机器区/人工区、原文完整性、稳定身份与已有人工关系；不让读取笔记、登记已读或重启任务自动触发整个资料库付费更新。已有显式知识同步仍是预览后应用。
4. 备份须在工作区不再有写者后执行：Web、CLI、调度、外部编辑器均应停止写入。备份/恢复到独立新路径，包含材料和任务 SQLite、vault/原件/笔记、画像与配置。恢复先校验清单与数据库，不覆盖现有目标。密钥和服务配置不随包发布，恢复后按需重新配置。SQLite 迁移事务同时提交结构和版本号；中断或失败不留下半升级。
5. 新生成的 macOS 自动任务固定当前工作区的 data、config 与 env 文件路径，不复制凭据值；后台最近结果与「LaunchAgent 已加载」分开展示。旧任务不会被升级自动修改。
6. M14 的原生 Obsidian 测试保留为可选兼容性验证，未完成状态不改写；Web 图谱独立发布。以后如做「继续」，只表示用户主动开始/继续或手工保存的章节、页码和时间戳，不把外链点击当成阅读进度。已提取全文可用于本地搜索，即使不适合当阅读器正文；搜索索引要能点击回实际原件/章节并标明缺失、摘要、部分或全文。

## 这轮不做

不增加采集器、OCR、embedding、主题批量推断、自动掌握度、站外阅读跟踪或新图谱布局。优先将后续导入鲁棒性与图谱维护拆为可度量子项目：导入记录技术失败与身份冲突，关系区分用户确认、文献证据、模型建议，并有去重、冲突审阅和可重建机制。
