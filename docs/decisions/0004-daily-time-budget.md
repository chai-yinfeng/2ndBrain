# 0004 — 以每日时间预算为分级主约束

- 状态：已接受
- 日期：2026-11-04

## 背景

原设计的分级只按条数配额（must_read ≤3、worth_it ≤10）。但用户每天可用于学习的时间有限（约 1.5–2 小时）、零散且有波动；一篇带长推导或大量框架代码的文章，读懂并验证可能要一两个小时，而一篇短博客只要十分钟。条数无法反映真实负担。此外，用户的经典博客阅读积累少，需要可控的补课节奏，避免一次性涌入。

## 决策

- **耗时估计**：L2 输出 `est_minutes`，按篇幅、数学推导密度、代码量估计"读懂并验证"所需时间。
- **时间预算为主约束**：tiering 以每日时间预算为主（settings：`daily_budget_minutes`，默认 105，可配），条数配额保留为上限。
- **深读标记**：单条 `est_minutes` 超过预算 `deep_read_ratio`（默认 0.6）的条目标记"深读"，可顺延到后续预算有余的日子。
- **积压**：未读的 must_read 计入"积压"，在 UI 显示；不无限累积，超过 `backlog_max_days`（默认 3）天降级到 fyi。
- **经典回补（M5）**：信源可设 `backfill: true`，抓取其历史归档中的经典文章，进入"温故 / 补课"池，按每日限额慢速释放。

## 后果

- 正面：每日推荐量与真实可用时间匹配；长文不会挤占全部预算却又不被丢弃；补课有节奏。
- 负面：依赖 LLM 估时的准确性（后续可用反馈中的实际阅读情况校准）；tiering 从简单排序变为带约束的选择（背包式贪心），测试用例更多；积压与顺延引入跨天状态。
- 涉及 milestone：M1（信源 `backfill` 字段，默认 false）、M2（`est_minutes`、预算约束 tiering）、M3（预算进度条、积压数量）、M5（backfill 实现）。
