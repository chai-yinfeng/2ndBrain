# 0028 — PDF 书目身份与可恢复材料归并

- 状态：已接受；具体验收与课程逐篇结果见 `docs/progress.md`
- 日期：2026-11-18
- 关联：ADR 0021、0026、0027

## 问题

直接 PDF 的内容流顺序可能把标题排到摘要之后，PDF Info 也可能只有排版文件名和 Administrator。没有 DOI 的作者公开稿因此只能以 URL 作标题，不能与已有出版记录可靠对上。反过来，文件扩展名为 PDF 并不证明它是论文。

## 决策

1. 通用提取复用 pypdf：物理首页布局识别题名、作者与明确的出版年份，结合可信 Info/标准 citation 元数据；不以文件创建日期冒充出版年，不新增单篇论文或网站专用规则。保留事实及证据，无法确认就留空；正文仍保留现有完整性/页数限制，不增加 OCR 或视觉理解。
2. DOI/arXiv 是强身份依据，但明确作者、年份或标识冲突仍拒绝自动匹配。无公共标识时，要求规范题名、完整作者名单、年份或出版信息同时一致，并有双方来源证据且在本地唯一；标题相同不够。公共标识一致的短/长题名可以合并候选，不擅自混合不同显式版本。
3. 所有入口仍走 `db.persist_material`。书目事实进入原有 provenance；补全保留稳定 ID、人工显示标题和阅读事实。标题检索可复用已经存下的同一全文，但保持原实际内容地址和版本，不将 provider 的出版声明贴到未核实的文件上。
4. 历史重复项通过 `sb items merge 主ID 重复ID` 预览，检查点 token 确认后应用。schema v15 追加 ID 映射和归并记录，不删除旧材料行、原件、反馈、任务历史或旧知识文件。不同非空个人笔记先拒绝，不能静默覆盖。
5. 归并持既有运行锁，数据库事务与文件变更之间使用可恢复 journal。检测到未完成归并时，预览也可能先执行恢复，因此它不是绝对无副作用的读取。检查点变化须重新预览；外部文件冲突保留 journal 并拒绝，不覆盖未知改动。
6. 主 ID 接收更完整正文及来源，旧 ID 的 GET 跳转到主材料，旧 ID 写入返回明确冲突。默认材料/阅读/处理队列排除映射项。机器页只调整来源与历史页撤下标记，正文和人工关系保留；旧 wikilink 仍能打开历史页。后续手动知识同步不得复活旧材料页或重新整理旧 ID。

## 边界

书目识别不是对论文真伪、出版版本或全文完整性的保证。公开元数据缺失、扫描 PDF、同题不同版本、课程页面引用错误仍需要明确选择或人工提供材料。课程验收区分真实网络记录、缓存回放、自动识别、人工候选选择和失败，不用预填课程字段制造“自动成功”。批量登记阅读事实不隐式触发整批付费知识整理。

arXiv 明确的提交年份另存 `preprint_year`，不当作会议出版年；只有已有日期确属预印本日期时，才用有证据的出版年补全。普通出版年份冲突仍拒绝，不能以“可能是预印本”一概跳过。真正的作者名单差异保留给人工复核，不删除PDF作者迎合元数据，也不扩大无公共标识的姓名匹配规则。
